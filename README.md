## Запуск на macOS

Нужны Java 17, ZooKeeper 3.9.6 и Python 3.12. Например, для установки Java и ZooKeeper через Homebrew:

```bash
brew install openjdk@17 zookeeper
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python scripts/cluster_demo.py
```

`cluster_demo.py` сама поднимает и затем останавливает три процесса. Скрипт создаёт `data/server-{1,2,3}/myid`; каталоги данных остаются локально. Порты клиентских подключений — 2181–2183, порты кворума и выборов отличаются для трёх локальных процессов. Все `server.N` одинаковы в трёх конфигурациях.

Для ручного изучения статуса ансамбля можно запустить `scripts/ensemble_hold.sh` в одном терминале, посмотреть роли через `scripts/ensemble.sh status` во втором и остановить процессы командой `scripts/ensemble.sh stop`.

Запуск создаёт `data/server-{1,2,3}/myid`; каталоги и журналы остаются локально. Порты клиентских подключений — 2181–2183, порты кворума и выборов отличаются для трёх локальных процессов. Все `server.N` одинаковы в трёх конфигурациях.

Для Docker подготовлен `compose.yaml` с ZooKeeper 3.9.6, уникальными томами данных и отдельными опубликованными клиентскими портами:

```bash
docker compose up -d
```

В Docker myid задаётся через `ZOO_MY_ID`. Скрипты эксперимента используют Python Kazoo и подключаются к локальным портам 2181–2183.

## Что запускает демонстрация

1. Считывает роли трёх серверов командой ZooKeeper `srvr`.
2. Останавливает один узел и подтверждает запись через оставшееся большинство.
3. Останавливает второй узел и фиксирует невозможность клиентской записи без большинства, затем запускает ансамбль снова.
4. Создаёт ephemeral znode и проверяет его удаление после закрытия ZooKeeper-сессии.
5. Запускает два координатора с таймаутом сессии 10 секунд. Первый координатор сохраняет результаты по чанкам, затем приостанавливается на 40 секунд. Второй получает лидерство и продолжает расчёт по общему чекпоинту.
6. Повторяет сценарий с `FENCING=0` и `FENCING=1`. Получатель результата хранит активную эпоху и указатель на последнюю запись. Без проверки эпохи поздняя запись старого координатора принимается; с проверкой отклоняется с `BadVersionError`.
7. Сравнивает пары, записанные координатором, с полным ожидаемым результатом ДЗ № 3.

Фактические журналы лежат в `logs/`, результаты и состояние указателя — в `results/`, PDF-отчёт — в `report/report.pdf`.

## Почему три узла

Кворум — большинство. В ансамбле из двух серверов при потере одного остаётся только половина, поэтому подтвердить записи нельзя. В ансамбле из трёх при потере одного два узла сохраняют большинство. Четыре узла выдерживают те же один отказ, что и три: после двух отказов остаются два из четырёх, то есть ровно половина, а большинства нет. Для учебного ансамбля три узла дают проверку отказоустойчивости с меньшим числом процессов.

## Почему эпоху проверяет получатель результата

ZooKeeper выдаёт координаторам эпохи и управляет их сессиями, но вычислительный результат может записываться в отдельную БД, файл или другой сервис. ZooKeeper не участвует в атомарной транзакции этого хранилища. Получатель записи должен сам сравнить эпоху запроса с текущей и отклонить устаревшую операцию. В демонстрации SQLite-получатель выполняет это сравнение внутри одной транзакции вместе с обновлением указателя результата.

## Структура

- `config/` — три конфигурации ансамбля.
- `compose.yaml` — альтернативный Docker-запуск.
- `src/` — подсчёт пар, координаторы с чекпоинтом и получатель с проверкой эпохи.
- `scripts/` — управление серверами и исполняемый сценарий проверки.
- `data/` — данные Go-вакансий и эталонные пары из ДЗ № 3.
- `logs/` — журналы фактических запусков и измерение смены лидера.
- `results/` — итоговые указатели, восстановленные пары и сводка опыта.
- `report/` — отчёт PDF.
